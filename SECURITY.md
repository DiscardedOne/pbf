# Security Policy

## Supported versions

| Version | Security updates |
|---|---|
| 3.0.0 | Supported for the current public release |

Security support for later versions will be stated in their release documentation. Older or development-only snapshots may not receive fixes.

## Reporting a vulnerability

Please do **not** report an unpatched vulnerability in a public issue, discussion or pull request.

The preferred reporting route is GitHub's **private vulnerability reporting** feature on the PBF repository. Open the repository's **Security** tab, choose **Advisories**, and use **Report a vulnerability**. This route is available only after the repository owner enables private vulnerability reporting in the repository's security settings.

The repository owner must enable that feature before the repository is announced publicly. If it is temporarily unavailable, use the private contact method displayed on the repository owner's GitHub profile. Do not include exploit details in a public issue while waiting for a private channel.

Please include the affected PBF version, relevant environment information, steps to reproduce, expected and actual behavior, and any proof-of-concept needed to understand the issue. Avoid sending real credentials, customer data or unrelated private information.

## Scope and response

Reports may cover the PBF source, release builder, Agent-First bootstrap package, generated workspace runtime and distribution process. The maintainer will acknowledge and assess reports as reasonably practicable, coordinate a fix and disclosure, and publish an advisory when appropriate. No fixed response-time commitment is made by this policy.

For guidance on GitHub's private reporting feature, see [GitHub's documentation](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).
