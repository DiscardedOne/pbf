# Phase Registry — Configurable planning lifecycle

This file is the source of truth for phase numbers and display names used by status, graph and gate tooling. Add project-specific phases here when D0.02 proposes them. Phase numbers must be unique non-negative integers and should reflect the agreed sequence; numeric gates treat lower numbers as earlier phases. Update `_framework/WORKFLOW-PLAN.md`, D0.02 and gate rules when order/meaning changes.

| Phase | Name | Status | Notes |
|---:|---|---|---|
| 0 | Framework setup & vision capture | active | Create vision playback and adaptive documentation architecture. |
| 1 | Discovery & business framing | active | Problem, users, outcomes, constraints. |
| 2 | Product definition & requirements | active | Scope, journeys, behavior and quality requirements. |
| 3 | Domain, data & integrations | active | Domain model, lifecycle and dependencies. |
| 4 | High-level architecture | active | System context and architectural decisions. |
| 5 | Low-level technical design | active | Component, interface and data specifications. |
| 6 | Quality, security & operations | active | Verification and operational controls. |
| 7 | Delivery planning | active | Roadmap, build guide and release planning. |
| 8 | Coherence audit & sign-off | active | Cross-document audit and baseline approval. |
