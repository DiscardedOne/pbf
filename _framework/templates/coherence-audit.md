## Checklist
- [ ] Goals and success metrics are explicit and measurable where feasible.
- [ ] In-scope features map to goals; use cases map to features; requirements map to use cases/source.
- [ ] Requirements are atomic, prioritized, testable and have acceptance evidence.
- [ ] Domain concepts, data ownership, lifecycle, retention and invariants agree with requirements.
- [ ] Integrations include contracts, owners, terms/limits and failure behavior.
- [ ] Architecture addresses key quality attributes and its diagrams agree with prose.
- [ ] Each material choice has an ADR or explicit open/deferred status.
- [ ] Component and interface behavior includes validation, auth, errors, retries, idempotency/concurrency as relevant.
- [ ] Requirements/components have verification coverage; no unexplained traceability orphans.
- [ ] Threat model, privacy, operations, backup/recovery, performance and cost were considered proportionately.
- [ ] Terms, identifiers, numbers, versions, units and configuration are consistent.
- [ ] No hidden or blocking questions remain; accepted exceptions have owners and revisit triggers.
- [ ] Manifest, front matter, links, state, changelog, handoff and indexes are current.
- [ ] Owner explicitly accepts the planning baseline.
